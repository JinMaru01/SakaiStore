# Sakai Store — Architecture & Contracts

Sakai Store is a **game top-up web portal** for Cambodia (Mobile Legends, Free Fire,
PUBG Mobile, …). It replaces the Telegram-bot-only shop with a full website while
keeping Telegram for admin alerts/actions and customer order updates, and it is
built to be **promoted on a Facebook Page and TikTok** (share links, OG images,
pixels, channel promo codes, per-channel sales analytics, promo image + caption
studio).

```
Customer (from Facebook / TikTok / Telegram / Google)
   │  lands on /?utm_source=tiktok…  → first-touch attribution cookie (sk_attr)
   ▼
/games/[slug]  enter Player ID (+Zone) → pick package → promo code → "Pay with KHQR"
   │  POST /api/orders  (server computes price, stores attribution + channel)
   ▼
/orders/[code]  KHQR (ABA, ACLEDA, Wing, any Bakong app) + countdown
   │  polls GET /api/orders/[code] → server checks Bakong by md5 (throttled)
   ▼
paid ──▶ fulfillment (manual: admin gets Telegram alert with ✅/❌ buttons) ──▶ delivered
   │                                                     customer gets Telegram update (if linked)
   ▼
Admin: /admin (orders, games & prices, promo codes, settings, marketing studio, channel analytics)
```

## Stack

| Concern | Choice |
|---|---|
| Framework | **Next.js 16** App Router, React 19, TypeScript (`src/` dir, `@/*` alias) |
| Styling | Tailwind CSS v4 (CSS-first tokens in `src/app/globals.css`) |
| DB | PostgreSQL + **Drizzle ORM** (`drizzle-orm/node-postgres`), migrations in `drizzle/` |
| Validation | zod v4 |
| Payments | Bakong **KHQR** via `bakong-khqr` SDK + Bakong Open API `check_transaction_by_md5` |
| Auth (admin) | single password (`ADMIN_PASSWORD`) → HS256 JWT cookie via `jose` |
| Notifications | Telegram Bot API (fetch) |
| Tests | Vitest (unit + DB integration on `sakaistore_test`), Playwright (e2e) |

## Next.js 16 rules for this repo (read before writing code)

* **Cache Components is OFF** (`next.config.ts`). Use the "previous" model:
  every page that reads the DB must be dynamic — the root layout already reads
  cookies (locale), which makes every route dynamic. In route handlers that only
  read the DB, call `await connection()` (from `next/server`) first or export
  `export const dynamic = "force-dynamic"`.
* `params` and `searchParams` are **Promises**: `const { slug } = await props.params`.
  Use the global helpers `PageProps<"/games/[slug]">`, `LayoutProps<"/">`,
  `RouteContext<"/api/orders/[code]">` (generated by `npx next typegen`).
* `cookies()` / `headers()` are async.
* `middleware.ts` is deprecated → `proxy.ts` (Node runtime). We do **not**
  rely on proxy for auth; always call `requireAdmin()`.
* `next lint` is gone → `npm run lint` (ESLint CLI).
* Bundled docs: `node_modules/next/dist/docs/` — check them when unsure.
* Server-only modules start with `import "server-only"`.
* Do not use `export const runtime = "edge"`; everything runs on Node.

## Conventions

* **Money is integer USD cents** everywhere (`priceCents`, `totalCents`). Format with
  `formatUsd(cents)` / `formatKhr(cents, rate)` from `@/lib/utils`. Never trust a
  price from the client — the server recomputes from the DB.
* Validate every request body with zod. API errors are JSON
  `{ error: "<code>", field?: "<field>" }` with a 4xx status. Error codes are
  stable snake_case strings; the storefront maps them to i18n keys.
* Use `env()` from `@/lib/env` for configuration (never `process.env` directly in
  app code, except `NEXT_PUBLIC_*` in client components).
* UI: dark gaming theme. Use semantic Tailwind tokens (`bg-bg`, `bg-surface`,
  `bg-surface-2`, `border-border`, `text-fg`, `text-muted`, `bg-primary`,
  `text-accent`, `text-success|warning|danger|info`, `bg-brand-gradient`,
  `text-brand-gradient`, `font-display`) and shared primitives from
  `@/components/ui` (Button, Card, Input, Select, Label, FieldError, Badge,
  StatusBadge, Spinner). **Mobile-first** — most customers come from the
  Facebook/TikTok in-app browsers on phones.
* Icons: `lucide-react` for UI icons. Brand icons (Facebook, TikTok, Telegram,
  Messenger, …) are inline SVGs in `src/components/icons/brand.tsx`.
* Do not add npm dependencies. Everything needed is installed; if you truly need
  one, say so in your report instead of installing it.
* Game logos are trademarks: never hotlink official art. Games render a
  generated tile (accent color + initials) unless the admin sets `imageUrl`.

## Internationalization (customer UI: English + Khmer)

* Locales `en` (default) and `km`, cookie `sk_lang`. Admin UI is English-only.
* Messages live in `src/i18n/messages/<namespace>.ts` as `{ en: {...}, km: {...} }`
  with **identical keys** (enforced by `src/i18n/messages.test.ts`, including
  `{placeholder}` parity). Namespaces: `common, home, game, order, track, social, pages`.
* Server components: `const { t, locale } = await getT()` from `@/i18n/server`.
* Client components: `const t = useT()` / `useLocale()` from `@/i18n/client`.
* Keys are `namespace.path`, e.g. `t("game.selectPackage")`, `t("order.total", { amount })`.
* Language switch: server action `setLocale(locale)` from `@/i18n/actions`, then `router.refresh()`.
* Khmer text needs generous line-height; `:lang(km)` sets 1.75 globally.

## Data model (`src/db/schema.ts`)

* `games` — slug, name, publisher, tagline, currencyName, accentColor, imageUrl,
  idLabel/idPattern/idHelp, requiresZone/zoneLabel/zonePattern/zoneOptions,
  hashtags, featured, active, sortOrder.
* `packages` — gameId, name, amount, bonus, priceCents, compareAtCents, badge, supplierSku, active, sortOrder.
* `promo_codes` — code (UPPERCASE), type percent|fixed, value, maxDiscountCents,
  minOrderCents, maxUses/usedCount, gameId, **channel** (facebook|tiktok|telegram|other), startsAt/endsAt, active.
* `orders` — uuid id + public `code`, status, snapshot of game/package/player,
  pricing (unit, discount, total), promo, KHQR (`khqr`, `khqrMd5`,
  `paymentExpiresAt`, `paymentRef`, `paymentPayload`, `lastPaymentCheckAt`),
  timestamps (`paidAt`, `deliveredAt`), contact (`contactPhone`, `contactTelegram`,
  `customerTelegramChatId`), notes, `locale`, **attribution** (`channel`,
  `utm*`, `clickId`, `referrer`, `landingPath`), `ipHash`, `userAgent`.
* `order_events` — timeline/audit: type, message, actor (system|admin|telegram|customer), data.
* `settings` — key/value JSON, accessed only via `@/lib/settings` (`getSettings()`, `updateSettings()`).

Schema changes: edit `schema.ts`, then `npm run db:generate` and `npm run db:migrate`.

## Order lifecycle (`src/lib/orders/status.ts`)

```
pending_payment → paid → processing → delivered
pending_payment → expired | cancelled        expired → paid (late payment)
paid|processing → failed → processing (retry) | delivered | refunded
paid|processing|delivered → refunded
```

Every transition is a **conditional UPDATE** (`WHERE id = $1 AND status IN (<allowed from>)`
… `RETURNING *`). Only the caller whose UPDATE returned a row performs side
effects (order event, promo usage increment, notifications, fulfillment). This
makes payment polling, cron reconciliation and Telegram/admin clicks safe to race.

## Module contracts

### Catalog — `src/lib/catalog.ts` (server-only)
```ts
listGames(opts?: { includeInactive?: boolean }): Promise<GameWithMinPrice[]>   // sorted by sortOrder; minPriceCents for "from $x"
getGameBySlug(slug, opts?: { includeInactive?: boolean }): Promise<(Game & { packages: Package[] }) | null> // active packages sorted
getPackageForGame(gameId, packageId): Promise<Package | null>
```

### Orders — `src/lib/orders/*` (server-only)
```ts
// service.ts
createOrder(input: CreateOrderInput, ctx: CreateOrderContext): Promise<Order>
getOrderByCode(code: string): Promise<Order | null>
getOrderById(id: string): Promise<Order | null>
listOrderEvents(orderId: string): Promise<OrderEvent[]>
refreshOrderPayment(order: Order): Promise<Order>       // pending → checks provider (throttled ~4s/order), expires when past paymentExpiresAt
markOrderPaid(orderId, p: { ref?: string; payload?: unknown; actor: Actor }): Promise<Order | null>   // idempotent; then notifyOrderPaid + startFulfillment
markOrderProcessing(orderId, p: { actor: Actor; message?: string }): Promise<Order | null>
markOrderDelivered(orderId, p: { actor: Actor; message?: string }): Promise<Order | null>
markOrderFailed(orderId, p: { actor: Actor; reason: string }): Promise<Order | null>
markOrderRefunded(orderId, p: { actor: Actor; message?: string }): Promise<Order | null>
cancelOrder(orderId, p: { actor: Actor; reason?: string }): Promise<Order | null>
addOrderNote(orderId, p: { actor: Actor; message: string }): Promise<void>
linkCustomerTelegram(code: string, chatId: string): Promise<Order | null>
expireStaleOrders(now?: Date): Promise<number>
reconcilePendingPayments(limit?: number): Promise<{ checked: number; paid: number }>
type Actor = "system" | "admin" | "telegram" | "customer"
// pricing.ts
evaluatePromo(promo: PromoCode | null, ctx: { subtotalCents; gameId; now }): { ok: true; discountCents } | { ok: false; error: PromoError }
type PromoError = "not_found" | "inactive" | "not_started" | "expired" | "used_up" | "min_order" | "not_applicable"
// public.ts
toPublicOrder(order: Order, events?: OrderEvent[]): PublicOrder   // customer-safe DTO
```
Mark functions return the updated order, or `null` if the transition was not
allowed / already applied (caller should re-read and show current state).

### Payments — `src/lib/payments/*` (server-only)
* `PAYMENT_MODE=mock`: deterministic fake KHQR (still a valid EMV string), and
  `POST /api/orders/[code]/simulate-payment` marks it paid. Never available in `bakong` mode.
* `PAYMENT_MODE=bakong`: `buildKhqr()` uses `bakong-khqr` `IndividualInfo(BAKONG_ACCOUNT_ID,
  BAKONG_MERCHANT_NAME, BAKONG_MERCHANT_CITY, { currency: USD, amount, billNumber: order.code,
  expirationTimestamp })` → `{ qr, md5 }`; `checkTransactionByMd5(md5)` POSTs
  `{ md5 }` to `${BAKONG_API_BASE}/v1/check_transaction_by_md5` with
  `Authorization: Bearer ${BAKONG_API_TOKEN}`; `responseCode === 0` ⇒ paid. Verify the
  paid amount/currency match the order before marking paid.

### Player lookup — `src/lib/players/lookup.ts`
`lookupPlayer(game, playerId, zoneId?) → { ok: true; playerName: string | null } | { ok: false; error: "invalid_id" | "not_found" | "unavailable" }`.
Modes: `none` (validate format only, name null), `mock` (deterministic fake nickname).
Real providers can be plugged in later.

### Fulfillment — `src/lib/fulfillment/index.ts`
`startFulfillment(order)` — called after paid. `manual`: → processing (admin delivers
in-game, then clicks ✅ in Telegram or admin). `mock`: → processing → delivered.

### Notifications — `src/lib/notify/index.ts`
`notifyOrderPaid(order)`, `notifyOrderStatusChanged(order, previous)`. Never throw.
Implemented with Telegram in `src/lib/telegram/*`:
* admin chats (`TELEGRAM_ADMIN_CHAT_IDS`) get a paid-order alert with inline buttons
  `✅ Delivered` / `❌ Failed` (callback data `ord:dlv:<code>` / `ord:fail:<code>`).
* customers link their chat via `https://t.me/<TELEGRAM_BOT_USERNAME>?start=ord_<code>`
  and get status pushes.
* Webhook `POST /api/telegram/webhook` (checks `X-Telegram-Bot-Api-Secret-Token`),
  commands for admins: `/orders`, `/order <code>`, `/stats`; for customers: `/start ord_<code>`, `/status <code>`.

### Public HTTP API (used by the storefront client components)
| Method & path | Body | Success | Errors |
|---|---|---|---|
| `POST /api/players/lookup` | `{ gameSlug, playerId, zoneId? }` | `{ ok: true, playerName: string \| null }` | 400 `invalid_id`, 404 `not_found`/`game_not_found`, 429 `rate_limited` |
| `POST /api/promo/validate` | `{ code, gameSlug, packageId }` | `{ ok: true, code, description, discountCents, subtotalCents, totalCents }` | 400 `{ ok:false, error: PromoError }` |
| `POST /api/orders` | `{ gameSlug, packageId, playerId, zoneId?, playerName?, promoCode?, contactPhone?, contactTelegram? }` | 201 `{ order: PublicOrder }` | 400 `invalid_request`/`invalid_id`/`invalid_zone`/`game_not_found`/`package_not_found`/`promo_<PromoError>`, 429 `rate_limited`, 503 `payment_unavailable` |
| `GET /api/orders/[code]` | — | `{ order: PublicOrder }` (refreshes payment if pending) | 404 `not_found` |
| `POST /api/orders/[code]/simulate-payment` | — | `{ order }` (mock mode only) | 404 / 409 `not_pending` |
| `POST /api/orders/[code]/cancel` | — | `{ order }` (only pending_payment) | 404 / 409 `not_pending` |
| `GET /api/cron/reconcile` | `Authorization: Bearer $CRON_SECRET` | `{ expired, checked, paid }` | 401 |

```ts
type PublicOrder = {
  code: string; status: OrderStatus;
  gameSlug: string; gameName: string; packageName: string;
  playerId: string; zoneId: string | null; playerName: string | null;
  unitPriceCents: number; discountCents: number; totalCents: number; currency: "USD";
  promoCode: string | null;
  khqr: string | null;               // only while pending_payment
  paymentExpiresAt: string | null;   // ISO
  paidAt: string | null; deliveredAt: string | null; createdAt: string;
  paymentMode: "mock" | "bakong";
  telegramLink: string | null;       // t.me deep link to get updates, when bot configured
  telegramLinked: boolean;
  timeline: { type: string; at: string }[];   // customer-safe events (no admin notes)
};
```

### Marketing & social (`src/lib/marketing/*`, `src/lib/tracking/*`, `src/components/marketing/*`)
* `AttributionCapture` (root layout) stores first-touch `sk_attr` cookie (see `src/lib/attribution.ts`).
  `createOrder` reads it server-side and saves `channel` + utm fields.
* `TrackingScripts` (root layout) injects Meta Pixel / TikTok Pixel when env IDs are set;
  `track(event, params)` from `@/lib/tracking/client` fires standard events
  (ViewContent on game page, AddToCart on package pick, InitiateCheckout on order create,
  Purchase when paid — event id = order code for dedupe).
* OG images: site default + per game (`opengraph-image.tsx`), so links shared on
  Facebook/Telegram/TikTok bio show the game + "from $x".
* Promo image API `GET /api/promo-image/[slug]?format=square|portrait|story` (admin
  downloads and posts to Facebook/TikTok). English + numbers only (Satori cannot shape Khmer).
* Caption generator (EN + KM, Facebook post / TikTok caption / video script) with UTM links,
  `/admin/marketing` studio, channel analytics (orders & revenue by channel).
* Social UI for customers: footer/header social links, "Follow us" section with the
  follower promo code, share bar (Facebook, Messenger, Telegram, copy link, native share),
  floating chat button (Messenger/Telegram).

### Admin (`/admin`)
* `/admin/login` (password) → `/admin` dashboard, `/admin/orders`, `/admin/orders/[id]`,
  `/admin/games`, `/admin/games/[id]`, `/admin/promos`, `/admin/settings`, `/admin/marketing`.
* Layout `src/app/admin/(panel)/layout.tsx` calls `requireAdmin()`; every server action
  and admin route handler calls `requireAdmin()` / `requireAdminApi()` again.
